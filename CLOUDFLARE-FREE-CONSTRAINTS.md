# Ограничения бесплатного тарифа Cloudflare Pages применительно к PLAN.md

Документ проверяет, какие пункты плана (`PLAN.md`) **нельзя** реализовать на бесплатном
тарифе Cloudflare Pages, какие требуют внимания, а также есть ли **технические
(платформенные) блокеры** для реализации технического плана на Cloudflare (раздел 4a).

Источники лимитов (актуальны на дату проверки):
- Cloudflare Pages Limits — https://developers.cloudflare.com/pages/platform/limits/ (обновлено 2026-07-16)
- Cloudflare Pages Headers — https://developers.cloudflare.com/pages/configuration/headers/ (обновлено 2026-04-21)
- Скил `cloudflare/references/pages/gotchas.md` — таблица лимитов (Jan 2026)

---

## 0. Главный вывод

**Ни один функциональный пункт MVP из `PLAN.md` не блокируется бесплатным тарифом.**

Причина: по архитектуре (разделы 2.1, 2.3, 21, 22) приложение — это **статическое
клиентское PWA без backend**. Все данные живут локально в IndexedDB на устройстве тренера,
на сервер ничего не отправляется. Cloudflare Pages используется **только как статический
хостинг ассетов**.

План прямо запрещает (раздел 21) всё, что могло бы упереться в платные лимиты:

- backend API — не используется;
- Cloudflare D1 — не используется;
- Cloudflare KV — не используется;
- пользовательские аккаунты — нет;
- облачная БД / синхронизация — нет (раздел 27).

Следовательно, **лимиты Cloudflare Functions/Workers (CPU, запросы, subrequests, размер
скрипта) к этому приложению не применяются вообще** — Functions в проекте отсутствуют.

Ниже — разбор реальных ограничений статического хостинга и того, что из плана к ним
относится.

---

## 1. Что действительно ограничено на Free (но плану хватает)

Эти лимиты существуют, но по объёму план в них укладывается. Перечислены для полноты и
как «границы, которые нельзя переходить».

| Лимит Free | Значение | Отношение к PLAN.md | Статус |
|---|---|---|---|
| Файлов на сайт | 20 000 | Сборка Vite (`index.html` + хешированные JS/CSS/иконки/manifest) — десятки файлов | ✅ с огромным запасом |
| Размер одного ассета | 25 MiB | Крупнейший ассет — JS-бандл (React), единицы сотен КБ | ✅ |
| Билдов в месяц (Git) | 500 | Только если подключать Git-интеграцию; при `wrangler pages deploy` (шаг 11) — не расходуется | ✅ |
| Параллельных билдов | 1 | Один разработчик, одна сборка за раз | ✅ |
| Таймаут билда | 20 мин | Сборка Vite — секунды | ✅ |
| Правил в `_headers` | 100 | CSP (раздел 2.1) — единицы правил | ✅ |
| Длина одного header | 2000 символов | CSP-строка укладывается в 2000 символов | ⚠️ проверить (см. п. 3) |
| Custom domains на проект | 100 | Нужен максимум 1 домен | ✅ |
| Проектов на аккаунт | 100 | Один проект | ✅ |

## 2. Что НЕ покрывается бесплатным тарифом Cloudflare (но и не требуется планом)

Эти возможности платные или недоступны — но план их **сознательно не использует**,
поэтому это не блокеры, а подтверждение, что архитектура выбрана верно.

| Возможность | Тариф | Пункт плана |
|---|---|---|
| Pages Functions сверх 100k запросов/день | Требует Workers Paid | Не используется — backend нет (раздел 21) |
| CPU-время функции > 10 мс/запрос | Workers Paid | Не используется |
| D1 (SQL) | Свободный тариф ограничен; в плане запрещён | Явно исключён (раздел 21) |
| KV | Ограниченный free / платный; в плане запрещён | Явно исключён (раздел 21) |
| R2 / облачное хранилище backup | Платный сверх free-лимитов | Не используется: backup — локальный файл (раздел 16) |
| Синхронизация между устройствами | Требует backend/БД | Отложена (раздел 27) |

**Вывод:** нет ни одного пункта MVP (раздел 26), который упирался бы в платный тариф.

## 3. Пункты плана, требующие ВНИМАНИЯ (не блокеры, но проверить)

Это не запреты тарифа, а места, где статический Free-хостинг накладывает нюансы на
реализацию требований плана.

### 3.1. CSP через `_headers` (раздел 2.1, шаг 5, шаг 11)
- `_headers` работает на Free — **это не проблема**.
- ⚠️ Ограничение: **один header ≤ 2000 символов**. CSP из раздела 2.1 нужно уместить в
  этот лимит (сейчас укладывается). План уже страхуется дублирующим `<meta http-equiv>`,
  что снимает риск полностью.
- ⚠️ Нюанс Pages: `_headers` применяется **только к статическим ассетам**. Поскольку
  Functions нет — все ответы статические, ограничение не мешает.

### 3.2. Заголовки для Service Worker / PWA (разделы 24, 24.1)
- Precache и offline-работа целиком клиентские — Free их не ограничивает.
- ⚠️ Никаких серверных заголовков управления кэшем сверх `_headers` задать нельзя без
  Functions; для данного PWA (versioned-хеши ассетов, precache в SW) этого достаточно.

### 3.3. Deployment через `wrangler pages deploy` (шаг 11)
- Прямая загрузка (`wrangler pages deploy dist`) на Free работает и **не расходует
  лимит 500 Git-билдов/месяц** — билд идёт локально.
- Если вместо этого подключать Git-интеграцию — расход идёт из 500 билдов/месяц
  (для одного разработчика неактуально).

### 3.4. Лимит запросов на доставку приложения
- Отдача статики (загрузка/обновление PWA, раздел 2.2) на Free-хостинге Pages по трафику
  и числу запросов к статическим ассетам **не тарифицируется как Functions** и для
  одного тренера/небольшой группы не создаёт риска. Ограничение 100k/день относится к
  Functions, которых в проекте нет.

## 4a. Технические (платформенные) блокеры Cloudflare — проверка техплана

Отдельно проверено: есть ли **технические** ограничения платформы Cloudflare Pages
(не тарифные), которые мешают реализовать технический план (разделы 21–24.2, шаги 5, 9, 11
и «Ключевые инварианты»). Проверялось против:
- Pages Headers — https://developers.cloudflare.com/pages/configuration/headers/ (обновлено 2026-04-21)
- Pages Limits — https://developers.cloudflare.com/pages/platform/limits/

**Технических блокеров, делающих техплан нереализуемым на Cloudflare, не найдено.**
Всё критичное поведение — клиентское (IndexedDB, Service Worker, Pointer Events,
BroadcastChannel, транзакции) и от платформы хостинга не зависит. Ниже — точки, которые
технически поддерживаются, но требуют корректной реализации.

### 4a.1. SPA-роутинг / отдача `index.html` (раздел 24.1: «навигация всегда отдаёт index.html»)
- ✅ Поддерживается. Способы: SW отдаёт `index.html` из precache (как в плане), либо
  `_redirects` с правилом SPA-fallback (`/*  /index.html  200`). Лимит редиректов на Free
  (2100) с запасом.
- Технически **не блокер** — план реализует навигацию через Service Worker, что от Pages
  не зависит вообще.

### 4a.2. CSP через `_headers` (раздел 2.1)
- ✅ `_headers` парсится и применяется к статике на Free.
- Лимит **2000 символов — на строку**, а CSP в `_headers` пишется одной строкой на
  директиву → укладывается легко. **Не блокер.**
- ⚠️ Нюанс не Cloudflare, а браузера: директивы `frame-ancestors`, `form-action`,
  `base-uri` **игнорируются** при доставке через `<meta http-equiv>`. План использует
  `<meta>` как дублёр — эти три директивы будут действовать **только** из `_headers`.
  Это ограничение спецификации CSP, не Cloudflare; на Pages `_headers` их отдаёт
  корректно. **Не блокер**, но `<meta>`-дублёр не заменяет `_headers` для них.

### 4a.3. `connect-src 'self'` и отсутствие backend (разделы 2.1, 21, 24)
- ✅ Полностью совместимо с Pages: приложение не делает кросс-origin запросов, backend
  не нужен. Static-only деплой — штатный сценарий Pages. **Не блокер.**

### 4a.4. Service Worker, скоуп и обновление (разделы 24, 24.1, шаг 9)
- ✅ SW регистрируется с origin-скоупом; Pages отдаёт `sw.js`/workbox-ассеты как обычную
  статику. `SKIP_WAITING` / `controllerchange` / `skipWaiting()` — клиентские API,
  платформа не вмешивается. **Не блокер.**
- ⚠️ Требование «SW не кэширует кросс-origin» (2.1) — забота реализации, не Pages.

### 4a.5. HTTPS для PWA/persistent storage (разделы 3.1, 19.2, 24)
- ✅ Pages отдаёт всё по HTTPS (в т.ч. на `*.pages.dev` и на custom domain на Free). Это
  выполняет требование secure context для Service Worker, `storage.persist()` и
  установки PWA. **Не блокер.**

### 4a.6. Web App Manifest, иконки, offline (разделы 24, 26)
- ✅ Манифест и иконки — обычные статические ассеты; число файлов << 20 000. **Не блокер.**

### 4a.7. IndexedDB, транзакции, `dataEpoch`, миграции (разделы 19.1–19.2, 24.2)
- ✅ Полностью клиентские, к хостингу отношения не имеют. Ни бесплатный, ни платный тариф
  на них не влияет. **Не блокер.**

### 4a.8. BroadcastChannel-протокол restore (раздел 17)
- ✅ Клиентский API между вкладками одного origin; Pages не участвует. **Не блокер.**

### 4a.9. Deployment `wrangler pages deploy dist` (шаг 11)
- ✅ Прямая загрузка поддерживается на Free; `_headers` в `dist` применяется в проде.
  **Не блокер.**

**Итог по техплану:** каждое требование либо чисто клиентское (и потому вне зоны влияния
Cloudflare), либо штатно поддерживается статическим хостингом Pages на Free. Технических
блокеров нет. Единственный содержательный нюанс — CSP-директивы `frame-ancestors` /
`form-action` / `base-uri` работают только из `_headers`, а не из `<meta>` (ограничение
спецификации CSP, не платформы).

## 5. Заключение

- **Блокеров бесплатного тарифа для реализации `PLAN.md` нет.**
- Архитектура «статический PWA + локальный IndexedDB + локальный backup-файл» специально
  спроектирована так, чтобы полностью помещаться в Free-план Cloudflare Pages.
- **Технических (платформенных) блокеров Cloudflare для техплана также нет** — см.
  раздел 4a: всё критичное поведение клиентское либо штатно поддержано Pages.
- Единственные точки контроля (не блокеры): длина CSP-строки в `_headers` (≤ 2000 симв.,
  считается на строку); директивы `frame-ancestors`/`form-action`/`base-uri` действуют
  только из `_headers`, а не из `<meta>`; способ деплоя (прямая загрузка `wrangler` не
  тратит лимит Git-билдов).
- Платные сервисы понадобятся **только** при выходе за рамки MVP — синхронизация между
  устройствами, аккаунты, облачная БД (раздел 27), — что планом отложено.
