# PLAN-DIARY-IA — единая информационная архитектура дневника замечаний

## Статус

Одобрено пользователем после консультации с oracle. Документ фиксирует решения
и план работ. Реализация выполняется отдельными worker-хендоффами по этапам
ниже; каждый этап проходит обязательный review.

**Выполнено:** §5 (порядок/вложенность дневника) — `RemarksScreen` и
`TrainingRemarksScreen` теперь рендерят для ПП-3 строго дерево «общее
замечание упражнения → список серий, внутри каждой серии сначала её
собственное общее замечание, затем вложенные замечания её выстрелов»,
вместо прежнего плоского списка замечаний выстрелов, который рендерился
перед списком серий. Флэт-список замечаний выстрелов теперь используется
только для standalone-серии/legacy-тренировки (где вложенность не нужна —
все выстрелы принадлежат одной серии). См. `pp3SeriesComment` /
`pp3SeriesShotList` (`RemarksScreen.module.css`) и `seriesNestedComment` /
`seriesNestedList` (`TrainingRemarksScreen.module.css`) — визуальный отступ
+ левая граница-«ветка» дерева. Переходы, редактирование/удаление и запрет
создания shot comments вне мишени не изменились.

## Зафиксированные решения пользователя

1. Добавляем **отдельные общие замечания для каждой серии ПП-3** — новый
   store/repo `seriesComments`, не смешиваем их с существующим общим
   замечанием всего упражнения (`generalComments`). Это два независимых
   уровня записи.
2. Переименовываем верхний пункт меню/раздел **«Замечания»** в **«Дневник»**.

Оба решения меняют предыдущее допущение из `PLAN-GENERAL-REMARKS.md` (там
общее замечание относилось только к целому самостоятельно запущенному
элементу тренировки) и предыдущее допущение из `PLAN-SCOPED-REMARKS.md` (там
для ПП-3 отдельная серия только показывала общее замечание упражнения "с
пометкой", без возможности завести своё). Начиная с этого плана — у серии
ПП-3 есть собственное общее замечание, независимое от замечания всего
упражнения.

## 1. Диагностика текущего хаоса

Существующая реализация (после `PLAN-GENERAL-REMARKS.md` и
`PLAN-SCOPED-REMARKS.md`) смешивает разные по смыслу действия под одним
словом «Замечания»:

- замечание к конкретному выстрелу (`CommentRecord`, экран мишени);
- общее замечание конкретной серии/упражнения (`GeneralCommentRecord`,
  привязано к `trainingId` целиком);
- общий список замечаний всего спортсмена (`RemarksScreen`);
- scoped-экран одной тренировки/серии (`TrainingRemarksScreen`).

Проблемы:

- Для ПП-3 серия внутри упражнения не имеет собственного общего замечания —
  показывается замечание всего упражнения с пометкой, что вводит в
  заблуждение: непонятно, к какому уровню относится текст, который
  редактируешь.
- Навигация построена на разрозненных `onBack`/`returnTo`/восстановлении
  `selectedSeriesView`, а не на едином стеке экранов — при добавлении новых
  переходов (мишень → дневник серии → дневник упражнения → общий дневник)
  риск потерять контекст возврата растёт с каждым новым переходом.
- Подписи кнопок неоднозначны: «Замечания» открывает то экран одного типа,
  то другого, в зависимости от того, где нажата кнопка.
- Общий список пока не показывает иерархию уровней (упражнение → его серии),
  только плоский список тренировок.

## 2. Целевая информационная архитектура

Три независимых, но связанных уровня записи:

```text
Выстрел         → CommentRecord        (shotId, trainingId)
Серия ПП-3      → SeriesCommentRecord  (trainingId, seriesNumber)
Упражнение/серия → GeneralCommentRecord (trainingId, весь элемент целиком)
```

Правила отображения:

- Для самостоятельной серии (`targetShotCount === 10`, не ПП-3) —
  используется только `GeneralCommentRecord`; отдельных `seriesComments` для
  неё не создаётся, так как это уже целый самостоятельный элемент, а не
  под-серия внутри упражнения.
- Для упражнения ПП-3 (`targetShotCount === 60`) — есть:
  - одно `GeneralCommentRecord` на всё упражнение;
  - до 6 `SeriesCommentRecord`, по одному на каждую серию (диапазоны
    выстрелов 1–10, 11–20, ..., 51–60, как в `trainingMode.ts`).
- Замечание к выстрелу (`CommentRecord`) существует независимо от уровня
  серии/упражнения и создаётся только с экрана мишени (см. §5).

### Терминология (переименование)

| Было | Стало |
|---|---|
| Раздел «Замечания» в навигации/меню | **Дневник** |
| `RemarksScreen` (общий список спортсмена) | Дневник — список по дням |
| `TrainingRemarksScreen` (scoped) | Дневник — тренировка/серия |
| «Замечания серии» / «Замечания упражнения» (кнопка в шапке) | «Дневник серии» / «Дневник упражнения» |
| «Общее замечание» (для ПП-3, неоднозначно) | «Общее замечание упражнения» / «Общее замечание серии N» |

Слово «Замечание» (единственное число) остаётся только для одной записи
текста (к выстрелу, к серии, к упражнению). Слово «Дневник» — только для
экрана-списка/навигации.

## 3. Модель данных

### Новая сущность

```ts
interface SeriesCommentRecord {
  id: string;
  athleteId: string;
  trainingId: string;
  seriesNumber: number; // 1..6 для ПП-3, соответствует getPp3SeriesShotNumberRange
  text: string;
  createdAt: string;
  updatedAt: string;
}
```

Ограничение: одна запись на пару `(trainingId, seriesNumber)`, аналогично
тому, как `GeneralCommentRecord` ограничен одной записью на `trainingId`.
Пустой текст не создаёт запись; сохранение пустого текста в существующей
записи удаляет её (то же правило, что и у `GeneralCommentRecord`).

### IndexedDB

- Новый store `seriesComments`, индекс/ключ по составному
  `trainingId + seriesNumber` (или отдельный индекс по `trainingId` с
  фильтрацией по `seriesNumber` в коде — выбрать по аналогии с существующим
  паттерном `generalComments`, см. `src/db/schema.ts`, `src/db/open.ts`).
- Аддитивная миграция: добавляется только новый store, существующие
  `generalComments` и `comments` не меняются и не мигрируются.
- Обратная совместимость со старыми backup-файлами без `seriesComments` не
  требуется (уже зафиксировано в `PLAN-GENERAL-REMARKS.md`, распространяем то
  же правило и сюда).

### Репозиторий

Новый `src/domain/seriesCommentRepo.ts`:

- `getSeriesComment(trainingId, seriesNumber)`
- `setSeriesComment(trainingId, seriesNumber, text)` — создаёт/обновляет/удаляет
  по правилу пустого текста
- `listSeriesCommentsByTraining(trainingId)`
- каскадное удаление вместе с тренировкой (см. `trainingRepo.ts`, по аналогии
  с `generalCommentRepo`)

### Backup/restore

- `seriesComments` включаются в `BackupFile` наравне с `generalComments`;
- экспорт/импорт новых записей;
- валидация и атомарность восстановления — по существующему паттерну
  `backupService.ts`.

## 4. Навигация: единый стек экранов

Вместо разрозненных `onBack`/`returnTo` на каждом экране — единый
навигационный стек в `App.tsx`:

```ts
type Screen = /* существующие варианты экранов */;

const [screenStack, setScreenStack] = useState<Screen[]>([initialScreen]);

function pushScreen(screen: Screen) {
  setScreenStack(stack => [...stack, screen]);
}

function popScreen() {
  setScreenStack(stack => (stack.length > 1 ? stack.slice(0, -1) : stack));
}

const currentScreen = screenStack[screenStack.length - 1];
```

Правила:

- Каждый переход между экранами дневника — это `pushScreen`, а не замена
  текущего экрана с ручной передачей контекста возврата.
- Кнопка «Назад» на каждом экране — это `popScreen`, без специальных случаев.
- Контекст (какая тренировка, какая серия) хранится в самом объекте `Screen`
  на вершине стека, а не восстанавливается отдельными пропами
  (`selectedSeriesView`, `restoreSeriesView` и т.п.) — эти поля можно вывести
  из стека или оставить как локальное состояние `TrainingScreen`, если экран
  остаётся смонтированным при пуше поверх него (уточняется на этапе
  реализации, в зависимости от того, размонтируется ли `TrainingScreen` при
  переходе в дневник).
- Маршруты дневника:

```text
TrainingScreen (серия/упражнение)
  → push: Дневник · Серия N / Дневник · Упражнение
    → push: Дневник · Серия M (только для ПП-3, переход упражнение → серия)
      → push: Мишень серии M (переиспользует TrainingScreen с тем же
        seriesNumber)
    → push: редактор замечания (общее серии / общее упражнения)

RemarksScreen (Дневник — общий список по дням)
  → push: Дневник · Тренировка (карточка дня/тренировки развёрнута)
    → push: Дневник · Серия N (для ПП-3)
      → push: Мишень серии N
```

- `popScreen` всегда возвращает на экран, с которого был выполнен `pushScreen`,
  без специальной логики восстановления состояния — состояние там, где было.

## 5. Единый дневник: дни → тренировки → серии → выстрелы

`RemarksScreen` (переименован в раздел «Дневник») группирует записи по датам,
внутри — по тренировкам, внутри ПП-3 — по сериям:

```text
29 августа 2026

Серия · 10 выстрелов · 66 (70.1)
  Общее замечание серии: ...
  Замечания выстрелов: №3, №7

Упражнение ПП-3 · 60 выстрелов · итоговый результат
  Общее замечание упражнения: ...
  Серия 1 · 10 выстрелов · результат — 2 замечания к выстрелам
  Серия 2 · 10 выстрелов · результат — нет замечаний
  Серия 3 · 10 выстрелов · результат — общее замечание серии, 1 замечание к выстрелу
```

Правила отображения:

- Тренировка (серия или упражнение) показывается, если у неё или у любого её
  под-уровня (общее замечание упражнения, любая серия ПП-3, любой выстрел)
  есть замечание, **или** если тренировка завершена и не имеет ни одного
  замечания — тогда показывается с действием «Добавить общее замечание»
  (правило из `PLAN-GENERAL-REMARKS.md`, п. 11, остаётся в силе).
- Для ПП-3 — список серий показывается всегда при разворачивании карточки
  упражнения, каждая серия кликабельна независимо от наличия замечаний.
- Клик по карточке тренировки/серии — `pushScreen` на «Дневник ·
  Тренировка»/«Дневник · Серия N».
- Клик по замечанию выстрела — переход к тренировке с открытым нужным
  выстрелом (существующее поведение сохраняется).

## 6. Единый редактор замечаний

Один компонент-редактор (переиспользование текущего `GeneralRemarkScreen`,
расширенного под три цели):

```ts
type RemarkTarget =
  | { kind: 'general'; training: TrainingRecord }
  | { kind: 'series'; training: TrainingRecord; seriesNumber: number }
  | { kind: 'shot'; training: TrainingRecord; shotId: string };
```

- `kind: 'shot'` в этом редакторе используется только для **редактирования
  существующего** замечания выстрела (открыто из дневника) — новое
  замечание к выстрелу через этот редактор не создаётся (см. §7).
- `kind: 'general'` и `kind: 'series'` — создание и редактирование в этом
  редакторе разрешены оба.
- Пустой текст при сохранении удаляет запись (единое правило для всех трёх
  видов).
- Заголовок редактора зависит от `kind`: «Общее замечание упражнения» /
  «Общее замечание серии N» / «Замечание к выстрелу №N».

## 7. Ограничение: создание shot comments только с экрана мишени

Подтверждённое ранее решение (см. недавние изменения в
`TrainingRemarksScreen`) распространяется на весь дневник:

- Новое замечание к выстрелу создаётся только на экране мишени
  (`TargetCanvas`/`TrainingScreen`), никогда — из дневника или из
  scoped-экрана серии/упражнения.
- Дневник и scoped-экраны показывают только **существующие** замечания
  выстрелов данного диапазона, с возможностью редактировать/удалять.
- Пустые диапазоны (выстрелы без замечаний) не показываются в списке
  замечаний выстрелов вовсе.

## 8. Scoped-переходы (сводная таблица)

| Откуда | Действие | Куда | Возврат |
|---|---|---|---|
| Мишень (TrainingScreen) | «Дневник серии»/«Дневник упражнения» (шапка) | Дневник · Серия/Упражнение текущей тренировки | Мишень той же тренировки/серии |
| Дневник · Упражнение (ПП-3) | Клик по серии N | Дневник · Серия N | Дневник · Упражнение |
| Дневник · Серия N | Ссылка "дата · N выстрелов · результат" | Мишень серии N | Дневник · Серия N |
| Дневник · Серия/Упражнение | «Добавить/Изменить общее замечание» | Редактор (`kind: general` или `series`) | Дневник · Серия/Упражнение |
| Дневник · Серия/Упражнение | Клик по замечанию выстрела | Редактор (`kind: shot`, только edit) | Дневник · Серия/Упражнение |
| Раздел «Дневник» (общий список) | Клик по карточке дня/тренировки | Дневник · Тренировка (аналог scoped) | Раздел «Дневник» |
| Completion modal (после завершения) | «Замечания» | Редактор (`kind: general` для только что завершённого элемента) | Completion modal / экран мишени |

## 9. Тест-план

- CRUD `seriesComments`: создание/чтение/обновление/удаление, включая
  правило «пустой текст = нет записи», ограничение «одна запись на
  `(trainingId, seriesNumber)»`.
- Независимость `seriesComments` от `generalComments`: изменение общего
  замечания упражнения не влияет на замечания серий и наоборот.
- Каскадное удаление `seriesComments` вместе с тренировкой.
- Backup/restore `seriesComments` (экспорт и импорт новых записей).
- Навигационный стек: `pushScreen`/`popScreen` для всех переходов из таблицы
  §8, включая многоуровневый: мишень → Дневник · Упражнение → Дневник ·
  Серия N → Мишень серии N → (назад) Дневник · Серия N → (назад) Дневник ·
  Упражнение → (назад) Мишень.
- Переименование: раздел навигации показывает «Дневник», а не «Замечания»
  (текстовая проверка в тестах меню/навигации).
- Редактор с тремя `kind`: корректный заголовок, корректное
  создание/редактирование/удаление для `general`/`series`, только
  редактирование (без создания) для `shot`.
- Отсутствие создания shot comment из дневника/scoped-экрана (регрессионный
  тест на уже принятое ограничение).
- Группировка общего дневника: день → тренировка → (для ПП-3) серии →
  выстрелы; корректный подсчёт количества замечаний на каждом уровне.
- Пустые состояния: серия ПП-3 без замечаний, упражнение без общего
  замечания, самостоятельная серия без замечаний — у каждого свой текст и
  свои доступные действия (без предложения создать shot comment).
- Миграция живых IndexedDB данных: открытие существующей базы без
  `seriesComments` не приводит к ошибке, store создаётся пустым.

## 10. Миграция живых данных

- Новый store добавляется в очередной `db.version(N)` апгрейд (см.
  `src/db/open.ts`), без изменения существующих store'ов.
- Апгрейд должен быть аддитивным: `db.createObjectStore('seriesComments', ...)`
  внутри `onupgradeneeded`, без чтения/переноса существующих данных.
- Проверить, что существующие пользователи (реальные IndexedDB базы без
  этого store) открываются без ошибок после обновления — добавить тест в
  `src/db/db.test.ts` на апгрейд с предыдущей версии схемы.

## 11. Этапы реализации

1. **Модель и данные**: `SeriesCommentRecord`, IndexedDB store/migration,
   `seriesCommentRepo`, backup/restore, каскадное удаление. Тесты репозитория
   и backup/restore.
2. **Навигационный стек**: ввести `screenStack` в `App.tsx`, перевести
   существующие переходы дневника (`TrainingRemarksScreen`, `RemarksScreen`,
   `GeneralRemarkScreen`) на `pushScreen`/`popScreen`, убрать разрозненные
   `returnTo`/восстановление `selectedSeriesView` там, где это возможно без
   потери поведения. Тесты навигации.
3. **Переименование**: «Замечания» → «Дневник» везде в UI (меню, заголовки
   экранов, подписи кнопок из таблицы §2). Обновить тексты в тестах.
4. **Scoped-экран серии ПП-3**: `TrainingRemarksScreen` показывает отдельно
   общее замечание упражнения и общее замечание текущей серии (два разных
   блока с явными подписями), с независимым созданием/редактированием
   каждого. Для упражнения в целом — список из 6 серий с переходом на каждую.
5. **Единый редактор**: расширить `GeneralRemarkScreen` (или создать общий
   компонент) под `RemarkTarget` из §6, с ограничением на создание для
   `kind: 'shot'`.
6. **Общий дневник**: перестроить `RemarksScreen` под иерархию день →
   тренировка → (серии ПП-3) → выстрелы согласно §5.
7. **Тесты и проверка**: полный прогон тест-плана §9, `npx vitest run`,
   `npm run build`.
8. **Деплой**: после зелёных тестов и build — автодеплой на Cloudflare Pages
   (staging) без отдельного запроса, согласно правилам проекта. Деплой на
   GitHub Pages (production) и commit — только по явному запросу
   пользователя.

Каждый этап — отдельный worker-хендофф с обязательным review перед переходом
к следующему.

## 12. Acceptance criteria

- У серии ПП-3 есть собственное общее замечание, независимое от общего
  замечания всего упражнения; оба видны и редактируются раздельно на
  scoped-экране серии.
- Верхний раздел/пункт навигации называется «Дневник», не «Замечания», во
  всех местах UI, где он упоминается.
- Все переходы между экранами дневника используют единый навигационный стек;
  многоуровневый сценарий (мишень → упражнение → серия → мишень серии →
  назад → назад → назад) возвращает пользователя туда, откуда он пришёл, на
  каждом шаге.
- Общий дневник показывает иерархию: день → тренировка → (для ПП-3) серии →
  выстрелы, с количеством замечаний на каждом уровне.
- Создание нового замечания к выстрелу остаётся возможным только с экрана
  мишени; ни один экран дневника не предлагает создать shot comment.
- `seriesComments` включены в backup/restore и каскадное удаление тренировки.
- Существующие данные (базы без `seriesComments`) открываются без ошибок
  после обновления схемы.
- `npx vitest run` и `npm run build` проходят на каждом этапе перед review.

## Вне рамок

- Аналитика/статистика — не входит (см. `AGENTS.md` §5).
- Изменение смысла самостоятельной серии (не-ПП-3) — у неё по-прежнему
  только одно общее замечание (`GeneralCommentRecord`), без под-серий.
- Обратная совместимость со старыми backup-файлами без `seriesComments` —
  не требуется (аналогично `PLAN-GENERAL-REMARKS.md`).
