# PLAN-GENERAL-REMARKS

## Цель

После окончания серии или упражнения (там, где сейчас показываются кнопки «Просмотр» и
«Новое упражнение» / «Новая серия») добавить кнопку «Замечания» — возможность записать
замечание общего характера по завершённому элементу тренировки. Предусмотреть сценарий, когда
тренер сначала нажимает «Просмотр», чтобы поправить последний выстрел, и только затем переходит
к записи общего замечания. Страницу «Замечания» преобразовать в вид дневника, где видны и
замечания по отдельным выстрелам, и общие замечания по завершении серии/упражнения.

## Зафиксированные решения пользователя

1. «Серия» и «упражнение» в этом сценарии — это самостоятельно запущенный элемент тренировки
   (одна `TrainingRecord`). Общее замечание относится к конкретному завершённому элементу
   (к этой серии или к этому упражнению целиком), а не к под-сериям внутри упражнения.
2. Кнопка «Замечания» добавляется в completion modal рядом с существующими кнопками
   «Просмотр» и «Новое упражнение» / «Новая серия».
3. Порядок действий: пользователь может сначала открыть «Просмотр» и изменить последний
   выстрел, затем вернуться — после возврата снова показывается окно завершения, и из него
   можно перейти в «Замечания». Переход в просмотр не создаёт и не блокирует запись общего
   замечания.
4. Запись общего замечания открывается на отдельном экране (не в модальном окне).
5. Общее замечание можно редактировать позже — не только сразу после завершения, но и зайдя
   на страницу «Замечания» (дневник) в любой момент.
6. Страница «Замечания» становится хронологической лентой: дата → упражнение/серия →
   общее замечание (если есть) → замечания отдельных выстрелов (если есть), в рамках этой же
   тренировки.
7. Модель данных: отдельная сущность общего замечания (general comment), привязанная к
   `trainingId` (не к `shotId`), в отличие от существующих shot-level замечаний. Тип элемента
   («серия» или «упражнение») определяется по существующим полям тренировки (например, по
   целевому количеству выстрелов/режиму), без изменения смысла остальных данных.
8. Backup/restore: общие замечания должны попадать в существующий JSON backup (экспорт и импорт
   новых записей). Обратная совместимость со старыми backup-файлами без общих замечаний
   не требуется — поддержку чтения старых backup-файлов без этого поля можно не сохранять.
9. Каскадное удаление: при удалении тренировки должно удаляться и её общее замечание —
   без осиротевших записей.
10. Обязательно покрыть тестами (vitest) и проверить `npm run build` перед сдачей на review.
11. Завершённые серии/упражнения (`completedAt !== null`), у которых нет ни общего, ни
    shot-level замечания, должны быть доступны в дневнике («Замечания») для создания первого
    общего замечания позже, а не только сразу после завершения из completion modal. Такая
    запись показывается в дневнике с действием «Добавить общее замечание», которое открывает
    тот же `GeneralRemarkScreen`. После сохранения текста запись остаётся видимой уже как
    обычная запись с общим замечанием (та же кнопка/переход, что и у существующих).

## Порядок реализации (для последующего worker-хендоффа)

1. Модель данных и репозиторий:
   - новая сущность `GeneralCommentRecord` (id, athleteId, trainingId, text, createdAt,
     updatedAt), привязанная к `trainingId`;
   - IndexedDB store/индексы в `src/db/schema.ts`, `src/db/open.ts`;
   - репозиторий (`src/domain/generalCommentRepo.ts` или расширение существующего слоя),
     экспорт через `src/domain/index.ts`;
   - пустой текст не создаёт запись; сохранение пустого текста в существующей записи удаляет её.

2. Backup/restore:
   - включить общие замечания в `BackupFile` (`src/domain/backupService.ts`);
   - экспорт и импорт новых общих замечаний;
   - валидация и атомарное восстановление;
   - обратная совместимость со старыми backup-файлами не требуется.

3. Completion modal:
   - добавить кнопку «Замечания» рядом с «Просмотр» и «Новое упражнение»/«Новая серия»
     в `src/screens/TrainingScreen.tsx` (или соответствующем компоненте модалки);
   - сценарий: Просмотр → правка последнего выстрела → возврат → снова completion modal →
     «Замечания»;
   - переход в просмотр не должен создавать пустую запись и не должен блокировать доступ к
     «Замечания» после возврата.

4. Отдельный экран общего замечания:
   - новый `src/screens/GeneralRemarkScreen.tsx` (+ CSS Module);
   - заголовок «Замечания по серии» / «Замечания по упражнению» (по типу элемента);
   - дата, краткая сводка (кол-во выстрелов, итоговый результат);
   - textarea с загрузкой ранее сохранённого текста;
   - сохранение/удаление при пустом тексте;
   - маршрут в `src/App.tsx` с возвратом в контекст завершённой тренировки.

5. Дневник на странице «Замечания»:
   - переработать `src/screens/RemarksScreen.tsx` (+ `.module.css`) в хронологическую ленту:
     дата → упражнение/серия (тип, кол-во выстрелов, итог) → общее замечание → замечания
     выстрелов;
   - завершённые (`completedAt !== null`) тренировки без единого замечания (ни общего, ни
     shot-level) показываются в дневнике с действием «Добавить общее замечание», открывающим
     `GeneralRemarkScreen`; после сохранения запись появляется как обычная запись с общим
     замечанием, без отдельного состояния;
   - незавершённые тренировки без единого замечания не показываются (как раньше);
   - переход по нажатию на общее замечание — на экран его редактирования (доступно и позже,
     не только сразу после завершения);
   - переход по нажатию на замечание выстрела — к тренировке/выстрелу, как сейчас;
   - избегать N+1 при загрузке данных: батчить/группировать запросы по тренировкам.

6. Каскадное удаление:
   - при удалении тренировки (`src/domain/trainingRepo.ts`) удалять связанное общее
     замечание;
   - проверить существующую политику удаления shot-level замечаний, не плодить новые
     сценарии осиротевших записей.

7. Тесты:
   - CRUD общего замечания (создание/чтение/обновление/удаление), включая правило «пустой
     текст = нет записи»;
   - один general comment на одну тренировку;
   - удаление общего замечания вместе с тренировкой;
   - backup/restore общих замечаний (экспорт и импорт новых записей; поддержка старых
     backup-файлов без общих замечаний не требуется);
   - сценарий «Просмотр → правка последнего выстрела → возврат → Замечания»;
   - рендер кнопки «Замечания» в completion modal;
   - рендер дневника: группировка по тренировке, отображение общего и shot-level замечаний,
     подпись «серия»/«упражнение»;
   - редактирование общего замечания позже из дневника.

8. Проверка:
   - `npx vitest run`;
   - `npm run build`;
   - после успешного прохождения — автодеплой на Cloudflare Pages (staging) согласно
     правилам проекта, без отдельного запроса пользователя;
   - деплой на GitHub Pages (production) и commit — только по явному запросу пользователя.

## Вне рамок

- Изменение смысла под-серий внутри одного упражнения (например, ПП-3) — не рассматривается;
  общее замечание относится только к самостоятельно запущенному элементу тренировки целиком.
- Аналитика/статистика — не входит, как и в остальном проекте (см. AGENTS.md §5).
