# План: режим «Пристрелка»

## Статус

Реализовано. Код написан, протестирован (все тесты зеленые, сборка проходит успешно). Режим «Пристрелка» полностью внедрён.

---

## 1. Цель

Добавить новый режим тренировки **«Пристрелка»**: стрелок выбирает его рядом с уже существующими «Серия» и «Упражнение ПП-3». Пристрелка — до 99 выстрелов одной непрерывной последовательностью без деления на серии; после 99-го выстрела тренировка автоматически завершается. Стрелок может завершить раньше через кнопку «Назад».

---

## 2. Зафиксированные требования и UX-правила

### 2.1 Кнопки «Новое» — экран «Тренировки» (TrainingsScreen)

- Порядок кнопок в модальном окне: **Пристрелка**, **Серия**, **Упражнение ПП-3** — именно в таком порядке, пристрелка первая.
- Кнопки расположены вертикально, каждая на полную ширину (существующий паттерн `.choiceBtn`).
- После завершения пристрелки — возврат к состоянию с кнопкой «Новое», открывающей это же модальное окно с тремя режимами.

### 2.2 Досрочное завершение — кнопка «Назад» (TrainingScreen, режим pristrelka)

- Отдельную кнопку **«Новое»** на экране активной пристрелки **не добавлять**, чтобы не изменять текущий мобильный UI и сохранить Undo, лупу и комментарий к выстрелу в их существующих позициях.
- Досрочное завершение выполняется через **существующую кнопку «Назад»** с диалогом подтверждения.
- **Если пристрелка активна** (не завершена): нажатие «Назад» показывает диалог подтверждения с текстом «Завершить пристрелку?» и двумя действиями:
  - **«Завершить»** — выставляет `completedAt` текущей пристрелке, затем открывает модальное окно выбора типа следующей тренировки.
  - **«Отмена»** — закрывает диалог, пристрелка продолжается.
- **Если пристрелка уже завершена** (автоматически после 99 выстрелов): кнопка «Назад» работает как обычно — возврат к экрану тренировок.

### 2.3 Выбор следующей тренировки после завершения пристрелки

- После **досрочного завершения** (подтверждение через «Назад»): сразу открывается модальное окно выбора типа следующей тренировки.
- После **автоматического завершения** (99-й выстрел): используется существующий экран завершения, затем модальное окно выбора типа следующей тренировки.
- Модальное окно выбора содержит ровно **два варианта**:
  1. **Серия**
  2. **Упражнение ПП-3**
  — пункт «Пристрелка» в этом модальном окне **не предлагается**.

### 2.4 Лимит и завершение

- Максимум **99 выстрелов**. После 99-го выстрела тренировка автоматически завершается (существующий механизм `completedAt` + `targetShotCount`).
- Undo последнего выстрела работает даже после достижения лимита (существующее поведение).

### 2.5 Структура выстрелов

- Выстрелы идут одной непрерывной последовательностью (без деления на блоки-серии). Никаких блоков/групп, как в ПП-3.

### 2.6 Отображение на мишени (мобильный, TrainingScreen)

- **Сохраняется существующий механизм** отображения последних 10 выстрелов в две колонки. Этот механизм не меняется без необходимости.
- Все выстрелы пристрелки рисуются на мишени (не только последние 10), так же как и в других режимах. Список-колонки под/рядом с мишенью показывает последние 10 в существующем формате.

### 2.7 Комментарии / дневник

- **Один общий комментарий на всю тренировку** — аналогично механизму `GeneralCommentRecord` для «Серии». Используется **без изменений** в существующей инфраструктуре.
- **Отдельный комментарий к каждому выстрелу** — существующий механизм `ShotCommentRecord` (или аналогичный, используемый в RemarksScreen для shot-level комментариев). Не меняется.
- ПП-3-специфичные серийные комментарии (`seriesCommentRepo` с `seriesNumber`) **не применяются** к пристрелке.

### 2.8 Отображение в списке тренировок

- Мод-лейбл: `«Пристрелка · N/99 выстрелов»` — аналогично `getTrainingListLabel` для остальных режимов.

### 2.9 Обратная совместимость

- Все существующие записи (legacy, серия, ПП-3) продолжают открываться и работать без изменений.
- Схема DB не меняется: пристрелка хранится как `targetShotCount = 99`.

## 3. Модель данных

### 3.1 Кодирование режима (решено — не требует уточнения)

Режим выводится из `targetShotCount` так же, как сейчас:

| `targetShotCount` | Режим |
|---|---|
| `10` | `series` |
| `60` | `pp3` |
| **`99`** | **`pristrelka`** (новое) |
| `null/undefined/иное` | `legacy` |

Новое поле в схеме **не добавляется**. `DB_VERSION` **не меняется**.

### 3.2 Константы (добавить в `trainingMode.ts`)

```typescript
export const PRISTRELKA_SHOT_COUNT = 99;
```

### 3.3 `TrainingMode` (расширить union)

```typescript
export type TrainingMode = 'series' | 'pp3' | 'pristrelka' | 'legacy';
```

### 3.4 `getTrainingMode` (добавить ветку)

```typescript
if (training.targetShotCount === PRISTRELKA_SHOT_COUNT) return 'pristrelka';
```

### 3.5 `getTrainingListLabel` (добавить ветку)

```typescript
if (mode === 'pristrelka') return `Пристрелка · ${committedCount}/${PRISTRELKA_SHOT_COUNT} выстрелов`;
```

## 6. Решения, не требующие дополнительного уточнения

- **Кодирование режима**: `targetShotCount = 99`. Новое поле в схеме не нужно.
- **Порядок кнопок в TrainingsScreen**: Пристрелка, Серия, ПП-3 (зафиксировано пользователем).
- **Лимит**: 99 выстрелов (зафиксировано пользователем).
- **Структура**: нет блоков/серий, все выстрелы в одной последовательности.
- **Комментарии**: `GeneralCommentRecord` (на всю тренировку) + shot-level комментарии (к каждому выстрелу); `SeriesCommentRecord` не применяется к пристрелке.
- **Мобильное окно последних 10**: существующий механизм не меняется.
- **Совместимость**: миграция не нужна, `DB_VERSION` не меняется.
- **Undo после лимита**: работает по существующему механизму, изменений не требует.
- **Механизм досрочного завершения**: используется существующая кнопка «Назад» с диалогом подтверждения («Завершить» / «Отмена»). Отдельная кнопка «Новое» на экране активной пристрелки не добавляется — мобильный UI и расположение Undo, лупы и комментария к выстрелу не меняются.
- **Выбор после завершения**: всегда только Серия / ПП-3, без Пристрелки — независимо от того, завершена ли тренировка досрочно или автоматически.
